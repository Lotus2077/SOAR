## What the experiment actually tested

Both attempts used the original exposed repair seeds, public tasks and original
compact critic messages. Thinking was disabled. The per-episode envelope remained
eight calls, 8192 output tokens per request, 256000 input bytes, 120 seconds per
request and 600 seconds total. No new probe details or corrected reference source
were supplied to the model.

The repair_window profile requires checks or help at the fifth request when no
fresh passing check or earlier failed check exists. Cache reached that restriction
after two source-changing actions, but returned run_command. The recorded action
was denied before execution. No trusted early check ran and no test feedback was
delivered. This is an observed model/action-contract failure, not an unknown
provider outcome or an inferred command selection.

Retry voluntarily ran a passing trusted check on request four and submitted on
request five. It never needed the forced fifth-request restriction. Its submission
therefore does not establish that the schedule caused better completion.

## Quality and evaluation

The evaluator verified the submitted patch's admitted objective, exact run,
source-bound checks and composition against the original baseline. Both frozen
suites executed on that same patch with verified harnesses and cleanup. The
stronger date probes failed despite the original acceptance suite passing.

Two independent source reviewers rejected the submitted patch and also identified
incorrect accumulation of long decimal seconds, beyond the date-handling defects.
The added candidate tests do not cover that defect. Review is independent but not
blind to the study context; the reviewers
receive the public task and complete baseline/candidate sources without the new
evaluation results. No passing check substitutes for semantic review.

Before generation, both original reference patches failed one stronger probe each.
Those negatives remain unchanged. Separately versioned corrected positive controls
passed all four Docker suites, totaling seventeen methods, before dispatch. This
establishes test preparation for the observed cases, not universal reference
correctness. The corrected fixtures never replaced the model's original repair seeds.

## Decision

The two-of-two development acceptance gate failed. There is no advancement to
the four untouched confirmation tasks, no retry of either assignment, and no
quality-preserving savings claim. Earlier full-policy failures remain unchanged.
With zero accepted repairs, this batch has no defined cost per accepted repair;
zero incremental API fees do not establish useful savings.

Stop treating check timing alone as the next quality hypothesis. A host-owned
checkpoint can run its already-authorized visible check directly instead of asking
the model to select a restricted tool; that can address the observed dispatch
failure but cannot fix missing semantic coverage. The next policy proposal should
combine reliable host checkpoints with independently generated executable checks
derived from public requirements, accounting for their cloud generation cost and
test validity. Hidden probes must remain evaluation-only. This is a proposal for
the next bounded development test, not approval for a new paid batch or evidence
that the approach will succeed.
