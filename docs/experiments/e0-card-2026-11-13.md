## Hypothesis

The endpoint the owner now serves can carry SOAR's local volume work at zero fee. A
single probe run, plus the role fixtures, re-derives every stage bound and clock and
settles five things:
- a thinking policy for each role;
- whether structured output is usable for each role;
- the adapter path;
- K, the number of concurrent streams;
- whether the figures qualified on 2026-11-04 still apply.

E0 makes no claim about product quality.

## Arms and tasks

- **P1 to P9**, the existing probes. P1 reads the served alias, the model root basename,

## The five items of issue #47

1. **Is the endpoint's model the one qualified on 2026-11-04?** (Decision 1, review
   section 5.10.)
   - **Owner (2026-11-13): yes, it is the same model.** So E0 is a delta check: if probe
     P1 and the writer's `--compare-*` rows match the 2026-11-04 qualification, its
     figures stay admissible. If any row differs, none of them apply and E0 re-derives
     every bound.
   - Probe P1 reads the served alias, model root basename, context and engine version.
     The writer's `--compare-*` rows show whether each is consistent with 2026-11-04.
   - P1 can show a difference, but it cannot prove identical weights (review section
     5.10). The reader's identity check later compares only the alias and, under
     `flash_next_v1`, the context.
2. **The judge fixture's per-claim agreement level.**
   - **Owner (2026-11-13): 95%.** The judge reaches the level when it agrees exactly with
     the labels on at least 95% of the labelled claims.
   - **Labeller (owner, 2026-11-13): a cloud model, through its API, before the test.**
     - It is separate from the judge and sees no judge verdict.
     - It follows the labelling protocol of the judge-fixture pull request (#91), which
       also adds `pnpm fixture:judge` and its manifest.
     - Because the labeller is a cloud model, the claim set holds public and synthetic
       material only.
     - The labelling spend is capped at USD 1.00 in total.
   - The judge fixture runs only after #91 merges and the labelled set is pinned. Until
     then the judge stays evidence-only.
3. **P10's 95% rule binds the strict variant** (`strict: true`, the default of
   `--p10-strict`).
   - If the server refuses strict and accepts non-strict, the probe falls back to
     non-strict, and no structured output is proposed.
   - Source: BL-20261108-1459-serving-card-reader-design, decision (9) ("Owner defaults
     recorded here"): strict by default, the probe's default.
4. **The planner fixture.**
   - Conditions `legacy-thinking`, `flash-thinking` and `thinking-off`, with 10 repeats
     each and an extraction call budget of 40, as the manifest proposes.
   - **The r3 index must be produced first.**
     - The fixture reads a research index of version 2 and its `coverage.json`, which
       today's pipeline writes. The seven r3 runs found on the owner's machine on
       2026-11-13 all predate that format, so none can be pinned.
     - One zero-fee research run of the exposed r3 task (`r3-grid-batteries`) on

     - Then fill `indexSha256`, `briefSha256`, `sourceIdsSha256`, `sourceCount` and
       `mandatorySourceChunks` from that run, and set `status` to `pinned`. The
       fixture refuses a template or a mismatch before any request.
   - **Owner (2026-11-13): keep.** Reasoning text is kept for synthetic and public
     inputs.
     - P10 runs without `--strip-reasoning`.
     - The planner fixture keeps its raw replies; it has no strip option.
     - Why: the review's row E0 retains raw replies, and its stop list (section 5.8)
       stops "discarding raw replies on public and synthetic runs".
5. **P11's K-stream range and prefill sizes**: K in {1, 2, 4, 8} and prefill at 20k, 60k

## Decision rule

E0 changes these decisions (review row E0, last column):
- **Stage bounds and clocks**: each is set from this run's measurements. Under a
  confirmed item 1 with a matching P1, the run is instead a delta check against
  2026-11-04.
- **Thinking policy for each role**: from P10, P11 and the planner fixture's three
  conditions.
- **Structured output for each role**: proposed only where P10's strict variant is at
  least 95% valid. That needs at least 20 calls, assessed under the protocol hash it
  sent, with the requested variant run and no unassessed reply.
- **The adapter path**: legacy or `flash_next_v1`, from the adapter probe.
- **K**:
  - P11 measures decode concurrency at K = 1, 2, 4 and 8 for a one-sentence prompt, not
    at extraction-size prompts.
  - The writer always proposes K = 1.
  - The reader refuses an adopted K above 1 until 8.2b merges. After that it accepts one
    only with a zero-error P11 burst at that K.
- **Whether the 2026-11-04 figures apply**: item 1 together with P1.
- **The judge threshold**: criterion 8's judge threshold applies in E3 and E4, and
  criterion 3's in E4, only if the judge fixture reaches item 2's level. Otherwise:
  - the judge stays evidence-only;
  - under the stop list, cloud claim verification is reconsidered.
- **Serving-recipe work** (section 5.8): it stays stopped unless E0 shows a role-level
  gap.

## Stop rule (proposed by this card)

- **Stop before any request** if:
  - the probe's zero-fee guard refuses. It refuses a base that is not loopback without
    `SOAR_VLLM_COST_POLICY=local_zero_cost`, and a non-loopback `http` base without
    `SOAR_ALLOW_INSECURE_VLLM_HTTP=true`;
  - the planner manifest is still a template, or does not match.
- **Stop after P1, and record the run as a negative result,** if the endpoint does not
  serve or `/v1/models` does not list the configured alias.
  - Run `python3 scripts/serving-probe.py --only P1` first and check its output by hand.
    The probe neither compares the alias nor stops after a failed probe.
  - Only then run P1, P10, P11 and the adapter probe in one invocation.
- **Discard the run and re-run P1, P10, P11 and the adapter probe together** if a pull
  request that changes `researchProtocolSha256()` merges between the export and
  `pnpm probe:assess`.
- **Before committing:**
  - the card writer refuses a served alias that looks like a file path;
  - check the written card for anything that looks like an address.
