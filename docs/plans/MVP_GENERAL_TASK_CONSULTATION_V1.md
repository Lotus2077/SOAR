# Permission-aware consultation in general tasks

Status: **Approved for implementation and controlled synthetic verification.**
This plan grants no paid dispatch or private-data release. Its source audit found
reusable broker, grant, accounting and recovery mechanisms; no new agent loop is
needed. The current desktop still uses its fixed local model.

## Smallest useful change

Keep the local agent as coordinator. An optional consultation tool asks for help
with a question and selected artifacts. The host creates a bounded packet from
immutable checkpoints, records its coverage and inherited privacy restrictions,
then pauses the job. The tool request itself sends nothing.

The user sees the actual packet, destination, model, maximum charge and omitted
material. Approval binds that exact proposal; decline or revocation records the
decision. A host-configured consultant returns one tool-free response through the
existing broker. The local agent can continue within the original job's remaining
budgets. Consultant feedback is untrusted evidence, not user instruction or
independent acceptance. A size limit, confidence score or public-web permission
never authorizes cloud disclosure.

Use explicit local-only versus ask-before-consulting configuration at creation.
When no admitted consultant profile exists, show that limitation and keep the
consultation tool unavailable. Do not silently activate legacy cloud credentials
or attach the old coding router's source-bearing payloads.

## Required contract work

- Bind approval to packet, full context lineage, source checkpoint, destination,
  account/credential version, purpose, price profile and maximum reserved fee.
  Current grants omit the last two bindings. Consume the proposal/grant and
  reserve the charge atomically; permission cannot be reused or widened.
- Version the new session variant and retain old identity checks. Budget, time,
  requests and local/consultation counts survive restart; consultation consumes
  an ordinary model request as well as the shared broker allowance.
- Complete and checkpoint the proposal tool action before pausing. Do not leave
  a dangling operation that existing no-replay recovery would reject. Pending
  approval cannot become implicit final submission.
- Persist the settled consultant response before local continuation. Resume
  reads that response without another call. An unknown dispatch or missing
  durable response stops further inference and does not replenish allowance.
- Revalidate the exact preview, consent, deadline and frozen provider identity
  at commitment. Revocation before commitment prevents sending; afterward report
  possible disclosure, with best-effort cancellation and no recall claim.
- Keep credential-classified data denied. Selection and summarization preserve
  inherited restrictions. Desktop trials remain public/synthetic while actual
  inference transport, server trust and private-data qualification are open.

## Verification before a real consultant

First use controlled localhost receivers and the current offline tools: draft,
request, pause, exact preview/approval, one consultation, restart, local
continuation, immutable output/export and cleanup. Verify permission/price/context
drift and concurrent approval cannot send; pending, denied, revoked, settled and
unknown states survive restart without duplicate calls or reset counters. Retain
local-only and public-research regressions. These are mechanics tests, with no
paid provider and no claim of model quality improvement.

A later real consultation needs an explicit provider/profile, compatible settings,
current price, authorized session credential and exact packet/cap approval before
dispatch. Keep its first draft and independently assess any resulting correction.
The already rejected research memo remains a known failure, not a held-out test.
Routing quality and savings stay unproven until measured on accepted work.

## Implementation admission, September 14 local date

The continuing owner instruction authorizes this implementation and its controlled
receiver verification. Record this approval in the build log before runtime tests.
No real model, paid provider, private-data disclosure or revived old trial is
included. Controlled localhost receivers may simulate prices and failure responses;
those ledger amounts are test values, not API spending. Reuse the pinned offline
Docker image and normal desktop launcher, with at most eight new consultation
scenarios plus the four existing general/research regressions. The existing
research regressions retain only their exact synthetic public URLs and resolver.
Additional focused unit/integration checks may use local receivers without models.

Use a host-configured, session-credential consultant profile with explicit prices,
model, account/version, output and fee limits. It is unavailable by default. The
renderer receives availability and a bounded exact preview, never a secret. Every
consultant destination requires its exact priced grant even for public material.
One proposal per task is sufficient for this first route; declined or revoked
help returns to local work, while uncertain dispatch/missing response cannot replay.
A consultant request consumes the existing model allowance and shared request cap;
require space for the consultation and at least one remaining local action.

The feature must remain usable for arbitrary end-to-end tasks. It is not tied to
the exposed procurement examples or an output format. Do not silently classify
model confidence, zero tool exit status or another model's advice as acceptance.
The website mismatch failure remains a separate quality regression to address
with real verification, not a reason to widen disclosure or spending authority.
