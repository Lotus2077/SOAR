# Desktop website and editable presentation milestone

Status: **Approved for the bounded qualification and two conditional tasks below**
under the owner's instruction to continue building the MVP. This is a new
artifact milestone; the rejected research memo remains unchanged.

## Deliverable

Use the existing desktop general-agent loop to deliver one self-contained,
interactive procurement website and one three-slide editable procurement deck.
Both use the same two authored synthetic JSON inputs. The goals require
source-based arithmetic, conditional recommendations and usable artifacts.
The four initial task families remain examples, not a task-type restriction.

The prepared goals and independent criteria predate any model candidate. Keep
them unchanged. Before generation, qualify the evaluators with an independently
constructed correct control and meaningful incorrect controls. Preserve any
checker defect and corrected revision; a checker pass is never independent
visual or factual acceptance. No candidate repair or replacement is authorized
after evaluation in either task.

## Authority and limits

Qualification may use the already installed, qualified artifact image with
network disabled, non-root execution, no host mounts or provider credentials,
bounded scratch space and confirmed cleanup. Copy authored fixtures and tools
into that container. Website checks use isolated Chromium; deck checks use safe
ZIP/XML/workbook parsing followed by LibreOffice and Poppler on a copy. Keep
each qualification batch below ten minutes; individual candidate evaluation is
bounded to four minutes and four CPUs/four GiB RAM. No installation or image
change, cloud calls, downloads, publication or real private data are included.

After evaluator qualification and independent driver review, separately freeze
and admit **one website task** and **one presentation task** through the normal
desktop app. Each has at most twenty owned-local model calls, thirty tools,
fifteen minutes, no public GETs and zero declared API fees. No paid fallback,
retry, resume or unused allowance transfer. Only each goal and the two selected
JSON files enter the model context. Gold, criteria, controls and evaluation
receipts remain outside it. Confirm installed image/configuration and current
runtime identities before each task; credentials and endpoint values stay local.

These are new individually bounded tasks authorized by the owner's continuation,
not reuse of the closed research task's allowance. The app's existing request,
permission, immutable-input, pause/stop and cleanup mechanisms remain in force.
An uncertain dispatch or missing execution prerequisite stops that task; preserve
the result and do not describe it as a model quality verdict.

## Evidence and acceptance

Bind goal, inputs, checker revisions, qualified image, source/build, driver,
approval and configuration identities before dispatch. Join submitted output to
exact native export, unchanged inputs, settled request/fee counters, zero unknown
outcomes and confirmed app/container cleanup. Preserve incomplete tasks as such.

The website must pass source-derived arithmetic, discounts/conversion thresholds,
invalid-input and no-eligible states, keyboard operation, offline execution and
responsive checks. Independently inspect the desktop/tablet/mobile screenshots.
The deck must contain exactly three slides with native text/table/chart, matching
embedded workbook and useful notes, with no macros or external relationships.
Require a three-page LibreOffice render without repair, inspect every slide and
notes, and verify native table/chart edits survive a copy-based save/reopen.
This does not claim Microsoft PowerPoint compatibility.

Report mechanics and accepted/failed content separately. One task per artifact
does not estimate reliability, generalization or quality-preserving savings.
The app's generic independent-acceptance state remains unevaluated; these are
external evaluations. Hardware, electricity and operating costs are excluded
from zero local API fees. Broader general routing and real-private deployment
remain required gaps in the full MVP.

In parallel, design a permission-aware review route in the same runner and
broker. Do not modify a frozen executed build during these trials. Paid review
requires a concrete provider, exact packet and cost authority before dispatch;
design and deterministic tests need no paid calls.
