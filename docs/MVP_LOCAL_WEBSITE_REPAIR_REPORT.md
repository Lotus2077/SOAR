# Local website repair milestone

Status: **Real repair closed incomplete; exported draft rejected. Request-size
error handling implemented and verified separately. The full MVP is incomplete.**

One local-only desktop task attempted to repair the exposed synthetic procurement
page. It did not produce an accepted deliverable. This is development evidence,
not a fresh benchmark or a cloud-routing comparison.

## Established baseline

The unchanged failed website completed an independent browser evaluation:
**15 of 30 checks passed**. All fourteen pricing cases reported incorrect totals;
keyboard recalculation also failed. Initial controls, eight invalid-input cases,
three viewport checks, script/network checks and visible assumptions passed.
All three screenshots were retained and inspected. They show incorrectly scaled
amounts and a missing total for the supplier marked Too slow. The mobile table
requires local horizontal scrolling, which the original requirements permit.

The evaluator was independently checked against sixteen control pages: three
valid variants and thirteen intentional failures. Every expected outcome matched
in the resource-observed batch. Its thirty-six screenshots, source bindings,
result files and cleanup were independently reconciled. This qualification
followed two earlier batches that each matched fourteen of sixteen controls;
their incomplete captures remain recorded. Chromium's intermittent screenshot
issue is not proved fixed. The latest control and baseline runs completed.

## Real repair result

The fresh task received the original supplier data, policy and requirements,
plus the unchanged failed draft. It received no evaluator, gold, numerical
answers or reference implementation. Its partial result was exported through
the normal desktop flow without hand edits.

The existing owned endpoint passed one discovery GET and advertised the
configured model. This proves availability at that moment, not inference
quality. The task ran on the previously verified runtime with limits of twenty
model attempts, thirty tools, forty broker requests and fifteen minutes.
It stopped incomplete after 268.613 seconds: sixteen model starts, fifteen
completed responses, fifteen completed tools and fifteen settled broker requests.
No dispatch was unknown. Five model allowances and over ten minutes remained.
App, owned processes and containers closed cleanly. There were zero consultant
calls and zero public-source fetches. Local API fees are declared zero; device
and operating costs have not been converted into a savings claim.

a strict lower bound of 214,335 bytes against the unchanged 196,608-byte limit;

The exact 14,157-byte draft separately completed the qualified thirty-check
browser matrix: **15 passed and 15 failed**, the same failure set as the original.
All fourteen arithmetic cases and keyboard recalculation failed. All three

This diagnostic cannot turn an incomplete task into a completed workflow.

## Request-size correction

The approved narrow fix identifies a typed size rejection before broker dispatch,
records a host-owned marker with operation identity and exact byte counts, and
shows that the request was not sent. It retains the consumed model attempt,
saved artifacts, request limit and no-resume outcome. Actual unknown dispatches
and missing or invalid evidence remain blocked from replay. The displayed
counter is labeled model attempts.

The correction passed independent source review, **173 distinct focused checks**,
both application TypeScript checks and the normal production build. The checks
cover canonical UTF-8 size boundaries, no broker call above the cap, operation
markers, SQLite reopening, unchanged unknown-request blocking, budgets,
consultation and session behavior.

One complete scripted desktop regression then passed on the new build. A
210 KiB tool observation made the next request 219,675 bytes. The UI showed two
model attempts, one tool and the specific not-sent reason. The ledger contained
one settled request, zero unknown requests and zero fees/reservations. The exact
84-byte artifact exported before and after restart, saved state and ledger were
unchanged, resume was denied, and the app and owned container closed cleanly.
Root independently read the retained SQLite database, checked source and export
hashes and inspected both screenshots. This is execution/recovery evidence with
scripted responses, not artifact-quality acceptance.

The first host test batch had four new fixture assertion errors; correcting its
artifact-result access made all 57 controller cases pass. The first desktop
invocation also stopped on a fixture assumption that a local-only snapshot must
include an optional fee summary. Its actual ledger fees were zero. That failed
invocation did not reach export/restart; the separate corrected case did. Both
failures and their original sources remain retained.

## Acceptance and remaining work

Acceptance still requires correct behavior against the original requirements,
visual review and independent input/runtime/ledger/export/cleanup checks. Both
failed website jobs stay closed. The next useful quality intervention must help
the agent act on failed calculations and control repeated large tool output;
changing the status message alone cannot make the page correct.

The separate real consultation trial still needs its explicit session profile
and exact packet/fee decision. Accepted research output, practical input/output
handling, real-private boundary qualification and owner acceptance remain part
of the full MVP. This milestone alone does not establish production reliability,
cost savings or release readiness.
