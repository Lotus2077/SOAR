# Fresh comparison of cloud and automatic source admission

**Superseded as the next experiment, 2026-09-11.** The owner changed the product
priority to privacy >= quality > savings > latency and broadened the workload to
general end-to-end agentic jobs. See the [replacement design](MVP_PRIVACY_FIRST_AGENT_V1.md).
This proposal remains undispatched and confers no paid authority. The design below
is retained as historical preparation; its cost/latency gates must not be reused
as the acceptance criteria for the new private-agent pilot.

Status: Proposed execution design within the owner's continuing routing goal.
Preparation may proceed. This document does not open a paid batch; dispatch
requires its own exact recorded approval, reviewed source and evaluator bindings,
current historical admission and immutable freeze. The preceding one-episode
allowance is closed and cannot be reused.

Preflight superseded the initial unconditional local-critic arm before dispatch:
three baselines exceed the complete-source critic envelope. The next question is
whether [automatic source admission](MVP_AUTOMATIC_CRITIC_ROUTING_V1.md), using the
existing prepared-cloud and local-critic-repair policies, can preserve quality
and reduce API cost across the existing development cohort. Use
all six exposed tasks: cache discard, last extremum, Retry-After, ordered build
rules, option default and log redaction. Reuse their original public requirements,
source revisions, file scopes and visible commands. Do not choose only the task
on which the new policy has already produced a candidate. Keep the four untouched
confirmation tasks reserved. These are development results, not held-out proof.

Run six fresh paired blocks, one cloud control and one Automatic episode per task,
serially. Freeze three cloud-first and three Automatic-first blocks before dispatch.
Both arms
start from the same original source; do not seed prior patches, plans, critic
feedback, evaluator content or known defects. Do not include the preceding
single-task episode or historical cloud episodes in the paired totals.

Use the production prepared-cloud control with its existing deterministic
preparation, forty-request limit and USD 3 episode ceiling. Freeze Automatic's
actual source-bound selection receipts before dispatch: three oversized baselines
select the same prepared-cloud policy and ceiling; the other three are expected
to select the unchanged local-critic-repair policy with eight draft requests, one critique, four optional
repair requests, twelve cumulative local requests, thirteen total requests and
USD 0.70 per episode. Reserve two finishing requests in each local phase. Both
retain one 600-second deadline, final-only visible checks, the same frozen cloud
profile and pinned execution environment. Keep the admitted local model and
disabled local thinking. There is no full cloud solver fallback after a local
draft. Unequal call ceilings are deliberate policy controls, not a claim
of equal compute. Twelve episodes imply at most USD 29.10 new exposure and 399
model requests: nine cloud selections and three local-critic selections. Stop on
any selection mismatch instead of increasing authority. Include
all existing reservations and unknowns under the USD 150 stage ceiling.

Reuse the current production controller, claim-once session launcher, historical
admission, isolated evaluator and neutral review packaging. Keep batch scheduling
and reports in a new private experiment directory. Do not add a production
database migration, change model prompts, extend concrete policy budgets, or build another
general evaluation framework for this comparison. Bind current runtime source
independently of archived historical versions.

Before generation, freeze each task's existing independent checks and qualified
public-requirement supplements. The ordered-rules task uses both the original
five checks and the qualified twelve-method interaction suite. Use previously
qualified supplements for other tasks only with their existing control receipts
and exact identities; do not repair an evaluator after seeing new model output.
An unqualified or incompatible evaluator stops preparation, rather than silently
falling back to weak checks. Review exact final source in neutral packages with
policy, cost and critic verdict omitted. Check pairwise regressions against the
same public requirement after the separate candidate judgments.

Acceptance requires completed runtime submission, current final visible checks,
all frozen independent checks, no material source-review defect, complete
accounting and confirmed cleanup. A recovered patch from a failed runtime is
diagnostic only. Critic approval and generated tests are not acceptance.
Cloud's runtime checks apply its frozen exported patch in a fresh container;
they do not carry the native policy's explicit before/after source hashes.
Independent evaluation must bind the exact exported patch for both routes; do
not invent cloud check hashes. Keep all
six assignments in each arm's denominator, including failures and any unrun rows
after an early stop. Sum all actual and conservatively unresolved model charges.
Cost per accepted task is total arm API exposure divided by accepted tasks; with
zero accepted tasks it is undefined. Report full episode latency for every
attempt, including failures, and require all six terminal observations per arm
before applying the median-latency gate.

Stop new dispatch on unknown usage, infrastructure failure, unconfirmed cleanup,
source/configuration/selection drift or exhausted authority. No retry, replacement, resume
or post-result tuning. Where independent acceptance can be completed between
blocks, an additional material Automatic-arm regression is an early failure; retain
the unrun assignments. An early stop cannot pass. Advance only after a complete
comparison has no additional material Automatic-arm regression, at least as many
accepted tasks as cloud, at least 20 percent lower API cost per accepted task and
no more than 25 percent higher median episode latency. Incomplete evidence cannot
clear a gate. Only a passing development result opens separately frozen untouched
confirmation.

Generate the bounded batch before independent evaluation and source review; there
is no between-block semantic clearance in this implementation. Infrastructure,
unknown-outcome and cleanup stops remain immediate. Do not claim an early semantic
stop that the runner cannot perform.

Report aggregate Automatic results and its concrete cloud/local selection counts.
Cloud-selected tasks remain in its denominator and fee totals. Report whether repairs were requested, completed and independently accepted,
including false critique and missed defects. Local API fees of zero exclude the
owned device's approximately USD 3,500 purchase and its operating costs. No total
cost, payback, generalization, application-release or owner-acceptance claim
follows from this comparison alone.
