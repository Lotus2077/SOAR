# Privacy filter v2: state-of-the-art landscape (checked 2026-10-19)

Status: research note, lens "state of the art". It proposes nothing that is approved. It grants no runtime, private-data or spending authority. Every gate in `docs/PLAN.md` and `docs/plans/PRIVATE_WORK_DESIGN_V1.md` still needs its own recorded approval.

Sources: project files read read-only (design V1 §1-2, PLAN.md D15 / Branch B / "cloud help that respects the owner's rule", PRIVACY_FILTER_RESEARCH.md, `scanner.ts`, `secret-patterns.mjs`, `broker.ts`, `repair.ts`, and the local OPF trial under `.soar/privacy-filter`), plus web sources fetched today. Each number below says who measured it: **SOAR trial** (our own synthetic 60-case development split, 2026-09-11), **vendor** (the model's authors or model card), **independent** (a third party), or **semi-independent** (a third party who also sells a competitor).

## 0. What the filter has to do, restated against the code

1. **What leaves.** Under D15 a labelled (Tier-O) context may send one owner-approved packet of *derived* material to the cloud: today the repair critic packet (`repair.ts`: brief ≤ 24 KiB + text renderings of the draft files + host-check output, ≤ 64 KiB total, water-filled) and in general any broker body ≤ 192 KiB (`BROKER_MAX_BODY_BYTES`). Derived material still carries the client's name, the matter facts, the patient's history, the unpublished result: minimisation by structure is necessary but not sufficient.
2. **What the code does today.** `RulePacketScanner` runs five credential regexes and returns `{complete, blocked, detector}`; the broker refuses any packet whose scan is incomplete or blocked and records only the detector identity (`broker.ts` ~L354-364). OPF ran only in the offline calibration; it is **not** wired into the broker. "OPF as first pass" is therefore new wiring, not a re-ordering.
3. **Invariants that stand.** Exact-byte owner approval of every packet to a labelled context; never for regime-tagged contexts (`legal_privileged`, `health_phi`, `research_human_subjects`, `controlled_access_genomic`, `export_controlled_or_unpublished_ip`); every dispatch (local included) in the hash-chained audit log (P8); no automatic local→cloud fallback; no detector may authorise a disclosure (PRIVACY_FILTER_RESEARCH.md); pseudonymised packets are still personal data (design §1, GDPR Art 4(5) / PIPL Art 73). The filter proposes; the owner disposes. Nothing below changes that.
4. **What the September trial measured (SOAR trial, synthetic, n=60, not a production estimate).** Per-class typed recall for OPF, from `development-aggregate-v1.json`:

## 1. Taxonomy of layers that exist in 2026

| Layer | What it catches | What it cannot catch | 2026 exemplars |
| --- | --- | --- | --- |
| **L0 structural minimisation** | Everything that is never rendered into the packet | Anything inside the rendered text | SOAR `buildRepairPacket`; PAPILLON "prompt creator"; LLM-Redactor option B |
| **L1 deterministic rules** | Known credential formats, checksummed identifiers (national IDs, bank cards, IBAN, 统一社会信用代码), emails, URLs, phone formats, high-entropy strings | Names, addresses, free-text facts, novel secret formats | `secret-patterns.mjs`, Gitleaks, detect-secrets, TruffleHog, Presidio pattern recognisers, Philter |
| **L2 learned span detectors** | Names, addresses, dates, account numbers, secrets in prose; fast, offline, deterministic given weights | Facts without an identifier; context ("is this span needed?"); quasi-identifiers; inference | OPF and its fine-tunes, GLiNER2-PII, nvidia/gliner-PII, OpenMed Chinese 560M, Meddies-PII (unreleased), LFM2.5-PII, Kiji DistilBERT |
| **L3 local LLM as checker / rewriter** | Quasi-identifiers, confidential business facts, essential-vs-non-essential spans (contextual integrity), inconsistent placeholders, injected instructions | Deterministic guarantees; it can hallucinate, miss, or be injected | PAPILLON, PUFT (IBM), Need-to-Know (GRPO rewriter), SEAL / GRASP anonymisers, INTACT, RedacBench adversarial redaction, Rescriber, PRvL |
| **L4 whole-packet risk / verification** | Residual re-identification by inference, subject-level exposure, policy-conditioned leakage; post-rewrite literal re-occurrence; placeholder consistency | Nothing new; it scores and blocks | SPIA, "False sense of privacy", RedacBench propositions, k-anonymity-for-text (Papadopoulou/Lison), probabilistic k-anon PCD |
| **L5 formal mechanisms** | Bounded token influence (DP inference), DP paraphrase | Needs local logits; large utility cost; opaque ε | DP-Fusion, DP-Prompt, DP-BART, DP-GTR, PRISM |
| **L6 placeholder map + restoration** | Keeps utility: consistent `[PERSON_1]`, per-task HMAC-keyed vault, restore on return | Does not reduce what leaves | HaS, Kiji proxy, piighost, LLM-Redactor, PromptGraph |

The owner's example (OPF → local model → rules) maps to L2 → L3 → L1. The evidence below says the order that matters is: L1 and L2 **in union** first (cheap, deterministic, recall-oriented), L3 on the already-masked packet (context, inference, over-removal), L4 deterministic checks last (the only part that should ever say "pass" to the broker), with L6 wrapped around L2-L3. Reasons in §4.

### 2.5 Whole-packet risk, contextual integrity, k-anonymity, DP (L4-L5)

- **Inference-based leakage is the dominant residual.** [SPIA (ACL 2026)](https://arxiv.org/abs/2604.21211): even with >90 % of PII spans masked, subject-level inference protection falls to 33 %; non-target subjects stay more exposed than the target. ["A false sense of privacy" (2025-26)](https://arxiv.org/abs/2504.21035): Azure PII removal "fails to protect 74 % of information in MedQA"; DP helps but costs utility. [RedactionBench (2026)](https://arxiv.org/abs/2606.18782): 200 documents, 11 domains, 35 models; annotators agree 89 % on mandatory redactions but only **47.7 % on contextual** ones; "contextual redaction remains an unsolved problem". These are independent and they are the reason the owner, not a detector, must remain the final judge.
- **Contextual-integrity benchmarks** (what "does the task need this span?" looks like when measured): CI-Bench, [PrivacyLens](https://arxiv.org/abs/2506.04245) (frontier models leak in >25 % of agent actions; CI-RL on ~700 synthetic examples reduces it, code [EricGLan/CI-RL](https://github.com/EricGLan/CI-RL)), [PrivaCI-Bench (ACL 2025)](https://aclanthology.org/2025.acl-long.518.pdf), [CI-Work (2026)](https://arxiv.org/html/2604.21308v1), [AgentCIScope (2026)](https://arxiv.org/html/2610.19158v1), [IDP-Bench (2026)](https://arxiv.org/abs/2606.09908) (eight open models: >90 % recognise co-ownership of third-party data but 7/8 score <74 % on identifying secondary subjects — directly relevant to D15's "consent reminder for third parties' data"), [PII-Bench query-aware (2025)](https://arxiv.org/abs/2502.18545) (2,842 samples, 55 categories; "even SOTA LLMs struggle with query relevance, especially multi-subject"), [DelegateCI-Bench](https://arxiv.org/abs/2606.04067) (3,167; medical challenge 950).
- **k-anonymity for documents.** [Papadopoulou et al., LREC 2022](https://aclanthology.org/2022.lrec-1.476): Wikidata background knowledge as distant supervision decides which spans to mask for k-anonymity, then fine-tunes RoBERTa; [Papadopoulou et al., AACL 2022](https://preview.aclanthology.org/moar-dois/2022.aacl-main.18.pdf): risk from LM probabilities, web-search queries and a classifier, with an ILP picking masks under a risk threshold; [2023 indicator comparison](https://arxiv.org/abs/2310.14312). [Li, Yu, Hirschberg 2026](https://arxiv.org/abs/2608.09140) add an LLM-estimated k-anonymity objective to PAPILLON (Llama-3.2-3B best balance; PUPA-SD). TAB's own authors note k-anonymity "was designed for structured data"; the "false sense" paper argues consistent quasi-identifiers are hard to define in text. Verdict: a useful **scoring idea** for L4 (local 27B estimates "how many people in the relevant population match this packet"), not a guarantee anyone can claim.
- **Differential privacy.** [DP-Fusion (ICLR 2026)](https://arxiv.org/abs/2507.04531) ([code, PyPI `dp-fusion-lib`](https://arxiv.org/html/2507.04531v1)): token-level DP inference / document privatisation with Qwen-2.5-7B; PPL 1.42-1.46 vs DP-Prompt 4.3-8.4 (or >100 at narrow width), ε ≈ 16-66; m+1 forward passes per token, ~1.5× slower; needs local logits (so it can only run on the Jetson, never with gpt-6-sol); relies on an upstream NER oracle; evaluated on 100 ECHR documents. [Empirical calibration (2026)](https://arxiv.org/abs/2603.22968): ADePT and DP-BART protect most, DP-Prompt least; per-token ε budgets are not comparable to sentence-level ones. [PrivateNLP 2026](https://aclanthology.org/2026.privatenlp-main.7/): DP rewriting mutates style and communicative signature. [PRISM (AAAI 2026)](https://arxiv.org/abs/2511.22788): entity-risk-scaled LDP + cloud "semantic sketch" refined locally. Verdict: not a fit for SOAR's packets (derived plans, code, schemas need exactness; ε is uninterpretable to the owner; no closed-model path). Worth citing only to say why not.
- **Placeholder maps and restoration (L6).** [HaS (2023)](https://arxiv.org/abs/2309.03057) trained small hide/seek models (details not verified here); [PromptGraph (2026)](https://arxiv.org/abs/2607.10709) picks spans by a utility-dependency graph and restores placeholders only after local consistency checks; Kiji, [piighost](https://github.com/malteos/awesome-anonymization-for-llms) (MIT, pluggable detectors incl. an LLM detector) and LLM-Redactor all implement typed placeholders (`⟨EMAIL_1⟩`) with a per-session vault. SOAR already has the primitives (keyed HMAC of paths in P8; `digest`/`canonical` in contracts) to do this per task with no cross-task correlation.

## 3. Multilayer precedents

- **Casper (2024)**: browser extension with three local layers (rules → NER → in-browser LLM topic classifier); 98.5 % PII and 89.9 % sensitive-topic accuracy on 4,000 synthetic prompts (vendor-academic; no code found) — [arXiv 2408.07004](https://arxiv.org/abs/2408.07004).
- **DataFog**: regex → spaCy → GLiNER cascade (from the [awesome list](https://github.com/malteos/awesome-anonymization-for-llms)).
- **LLM-Redactor (2026)**: measured that NER placeholders + local rephrase + local-only answering compound (15.3 % → 0.6 % PII leak) while implicit disclosures stay at 43.6 % — the clearest quantitative argument that layers add, and that the implicit layer is the hard one.
- **DeIDClinic (2024)**: transformer PHI masking followed by a document-level residual-risk score (k-anonymity, l-diversity, co-occurrence) — [arXiv 2410.01648](https://arxiv.org/abs/2410.01648).
- **Presidio 2026** itself is a bus for unions: GLiNER/HF recognisers + pattern recognisers + an LLM recogniser (LangExtract via Ollama) + LLM-as-judge evaluation, with anonymiser operators for consistent replacement and salted hashing.
- **Archived / not a fit**: LLM Guard (protectai) is archived and read-only; Llama Guard and Granite Guardian do not classify PII; NeMo Guardrails' PII rail is GLiNER/Presidio underneath (secondary sources).

## 4. What a v2 pipeline would look like, and what each layer adds over OPF

Proposed shape (not approved): every stage writes a content-free receipt (detector identity hash, span counts by class, decision) into the P8 chain; the packet the owner sees is the output of the last stage, and the `packetSha256` that is approved is the hash of exactly those bytes.

| Stage | Component | Adds over OPF-alone (grounded in §0 gaps) | Cost / risk |
| --- | --- | --- | --- |
| **S0 minimise** | `buildRepairPacket`-style builders, per packet type (critique, plan, schema, code diff) with explicit allow-lists of what is rendered; strip metadata, comments, tracked changes (P4) | Removes whole classes of content before any detector; the only layer with a provable "never rendered" property | None |
| **S1 rules v2** | Vendored Gitleaks rule set + detect-secrets entropy/keyword plugins + checksum validators (CN 身份证, USCC, Luhn, IBAN, TW/HK IDs, passports) + the five existing patterns; **block** on credentials, **mask** on checksummed IDs | Targets OPF's worst classes: account_number R 0.13 and secret R 0.33 / 5 missed canaries. Deterministic, zero over-masking on validated formats, auditable by hash | Entropy heuristics flag hashes and sample keys; keep them as "mask" not "block" |
| **S2 learned union** | OPF (pinned, Viterbi) ∪ one GLiNER2-PII pass (typed IDs, banking, credentials, recall 0.72) ∪ one zh detector (OpenMed-Chinese-560M or an OPF fine-tune); span-level OR, class-aware merge | Independent error profiles: OPF strong on email/person/phone, weak on account/date/address; GLiNER2 strong recall on government/banking IDs; zh model covers names OPF misses (0.138 on zh PER). Union raises recall where the trial failed | Precision drops (GLiNER2 P 0.35); mitigated by S4 placeholders rather than deletion, and by the owner seeing the diff. ~1-5 s on Mac CPU |
| **S3 placeholder map** | Per-task vault keyed with an HMAC derived from the job (never reused across jobs, P6); consistent `[PERSON_1]`/`[ID_3]`; entity clustering so "Li, Wei" and "Wei Li" share a placeholder (Rescriber's failure); "preserve literals" list from the brief (task-critical quantities, public identifiers) | Converts over-masking from a utility defect into a reversible one; addresses the 3 literal failures and the 6 unevaluated identity-reference checks | Pseudonymised packets remain personal data (design §1); say so in the approval screen |
| **S4 local 27B review** | One fresh-context call on the masked packet with a fixed, hashed prompt and T=0, structured JSON output, no tools, packet declared as data (P4). Four questions: (a) residual direct/quasi identifiers and PII-free self-disclosures, (b) sentences that disclose confidential facts the brief does not need (essential vs non-essential, PUFT/Need-to-Know framing), (c) instruction-like text (injection), (d) placeholders whose removal breaks the task (over-removal). Output is an **edit plan** the host applies deterministically (same pattern as document review) | The only layer that can touch the **12/60 whole-context cases**, quasi-identifiers and inference leakage (SPIA 33 %, "false sense" 74 %). Evidence that this size works: Qwen3-4B 75.8 % security on RedacBench; 3B GRPO rewriter SLR 8 % vs Presidio 89.6 %; Llama3-8B zero-shot P 0.94; 27B is in the band Staab found close to GPT-4 | 64 KiB ≈ 15-20 K tokens: ~10 s prefill (1,790 tok/s measured) + 30-90 s output at 35 tok/s. Nondeterminism, hallucinated edits, injection: all bounded by host-applied plans and the final owner diff. Never a pass/fail authority |
| **S5 deterministic post-checks** | Re-run S1+S2 on the rewritten packet: no raw literal of any S2 span or vault value may re-occur; placeholder consistency; size cap; regime tags absent on the context; planted canaries absent; `preserve_literals` present; packet hash bound to the receipt chain | The only stage allowed to return `complete && !blocked` to the broker; makes the 27B's output verifiable rather than trusted | None beyond S1/S2 cost |
| **S6 owner approval** | Existing exact-byte grant, plus a diff view: original → masked → rewritten, with the S4 rationale and the IDP-Bench-style "third parties present" reminder (D15) | Unchanged invariant | Owner time; the whole point |

Why not "OPF → LLM → rules" in that order: rules are cheapest and should run before the LLM so the LLM never sees raw credentials; and the LLM's output must be re-scanned deterministically afterwards, so rules belong last as well. The LLM in the middle is right.

## 5. Shortlist worth trialling (ordered by expected gain per owner-hour)

1. **Rules v2 (S1)**: vendor Gitleaks TOML (MIT) + detect-secrets entropy/keyword plugins + checksum validators. *Adds:* account-number and secret recall where OPF scored 0.13 and 0.33; deterministic blocks. *Test:* the 12 canaries + CredData-style secrets + pii-bench-zh checksummed IDs. Zero model risk; no licence issue (avoid TruffleHog's AGPL).
2. **GLiNER2-PII as union member (S2)** — Apache-2.0, 0.3 B, CPU-ONNX capable. *Adds:* 42 typed classes with 0.72 recall on legal text (vendor), banking/government/credential types OPF lacks. *Caveat:* no CJK; precision 0.35 means it must feed placeholders, not deletions. *Test:* SOAR corpus en/mixed splits; count new true positives per 100 new false positives.
3. **A Chinese detector (S2)**: first A/B **OpenMed privacy-filter-multilingual-v2** (drop-in OPF fine-tune, Chinese in its 16 languages, no published numbers) against base OPF on the zh/mixed splits; then **OpenMed-PII-Chinese-560M** (XLM-R, vendor micro-F1 0.76 on its own zh split, INT8 ONNX). *Adds:* zh person/ID recall (OPF zh typed R 0.52; 0.138 on zh PER independently). *Test:* pii-bench-zh (Simplified, templated) + tw-PII-bench (Traditional) + SOAR zh split; both with span-level decoding that does not fragment.
4. **OPF fine-tune on SOAR synthetic data (S2, later)**: `opf train` with a custom label space adding matter/case numbers, MRNs, study/participant IDs, 统一社会信用代码, 身份证, and "confidential_business" as a *span* class where it is lexically marked. *Adds:* the tw precedent shows +18.6 pp strict F1 and new classes from 0 → 30-100 % with synthetic data only. *Cost:* GPU hours on the Jetson, a sealed confirmation split, and the risk of hard-negative false positives (77.5 % of hard negatives fired in the tw fine-tune).
5. **Local 27B contextual review (S4)**, zero-shot first, prompts adapted from IBM's PUFT and the Need-to-Know essential/non-essential framing, output as an edit plan. *Adds:* the only coverage of whole-context confidential facts, quasi-identifiers, injection text and over-removal. *Test:* extend the SOAR corpus with 40 derived-material packets (legal memo plan, clinical critique, grant/manuscript review, code diff with a private schema) annotated RedacBench-style with inferable propositions; measure security (propositions removed), utility (non-sensitive propositions kept), SLR/EA, plus a **local adversary pass** (the same 27B tries to recover each masked value and infer attributes, Staab/SPIA style) as the leakage metric. Report latency per packet.
6. **An 8B self-refining anonymiser on the Mac (S4 alternative, optional)**: SEAL/GRASP-style Llama-3.1-8B if weights are released under a usable licence; otherwise skip. *Adds:* adversarially distilled abstraction of quasi-identifiers at ~1 % of GPT-4o cost (vendor claim), running on the laptop so the Jetson stays free. *Risk:* Llama licence, unreleased weights, English-centric.
7. **INTACT-style truthful generalisation (S4 variant for research packets)**: for packets where facts matter (research, admin), replace spans with the most informative abstraction that survives the local model's own inference attack rather than with blanks. *Adds:* utility retention with <1 pp extra risk on TAB (independent). Uses the same 27B.
8. **Watch list, no trial now**: Meddies-PII (unreleased; the only model with zh+secrets+company_name and a 0.83 mean F1 claim), LFM2.5-PII (lfm1.0 licence; strong on TAB 0.867 vendor), REDACT and PIIBench releases (for stratified evaluation), Kiji (English-leaning DistilBERT).
9. **Not recommended**: Piiranha (NC-ND), LLM Guard (archived), DP rewriting (utility, interpretability, no closed-model path), guard models (no PII), Presidio as the detector (keep it at most as a recogniser bus / anonymiser operator library).

## 6. Risks and open questions

1. **Legal status does not change.** Every layer above produces a pseudonymised packet; design §1 says that is still personal data, and D15 makes cloud help per-task opt-in only, never regime-tagged. The filter reduces exposure; it does not create a "de-identified" category and SOAR must not call it one (design §6).
2. **Inference leakage is unsolved everywhere.** SPIA 33 %, "false sense" 74 %, RedactionBench 47.7 % human agreement on contextual cases, LLM-Redactor 43.6 % implicit leak even with three layers. The 27B review is a mitigation with no measured ceiling for our packets; the owner's judgement on the diff is the control.
3. **Union raises false positives.** GLiNER2 precision 0.35, OPF over-masks mixed-language text (95 chars / 20 cases). Placeholders plus a preserve-literals list keep utility, but the trial's 6 identity-reference checks are still unevaluated and need the vault to be built before they can be.
4. **The checker is a model too.** Non-determinism (Rescriber saw it at T=0 on an MoE), hallucinated edits, prompt injection from the packet. Mitigations: fixed prompt hash, T=0, structured output, host-applied plans, deterministic S5 re-scan, never a pass authority. Needs its own canary cases (injected "ignore previous instructions" inside a draft).
5. **Chinese remains the weakest measured area.** No independent Simplified-Chinese PII benchmark with realistic legal/medical text exists; pii-bench-zh is templated; OpenMed's zh numbers are the vendor's; OPF's Mandarin recall is 0.92 on synthetic (vendor) but 0.138 on real zh person names (independent, general NER). SOAR's own zh/mixed splits stay the gate.
6. **Benchmarks are mostly synthetic and often in-distribution.** nvidia/gliner 0.87 on Nemotron vs 0.39 on SPY; Piiranha 0.946 on ai4privacy; models trained on ai4privacy/Nemotron score high there. Vendor tables (Fastino, Meddies, OpenMed, Liquid) disagree with each other on the same baselines (OPF on SPY: 0.37 vendor-competitor vs 0.46 independent). Only exact-match on our corpus counts.
7. **Secrets beyond patterns.** OPF missed 5/12 canaries; GLiNER2 has `api_key`/`access_token` classes but unmeasured on novel formats; entropy rules false-positive on hashes. A code-diff packet type needs its own canary family (LLM-Redactor's WL4 is the model: 31.3 % residual leak even with three layers).
8. **Hardware and runtime.** Jetson: memory is not the constraint (27B FP8 + OPF ~3-4 GB + GLiNER ~1 GB + an 8B is still far below 128 GB) but unified memory means detector processes compete with vLLM start-up (design §5 reserve) and the Thor (sm_110, CUDA 13) PyTorch wheel for a second process must be verified; vLLM 0.20+ upstream is documented, standalone PyTorch for Thor is not (forum reports only). Mac: OPF measured p95 4 s; an 8B 4-bit fits (Rescriber on M-series ≥16 GB) but the sealed-confirmation preflight stall (iCloud-evicted files) was never diagnosed and will recur for any new 1-3 GB checkpoint on a synced path.
9. **Decoder correctness.** Every OPF-family model must run its constrained Viterbi decoder; the transformers pipeline and the WebGPU port fragment Chinese spans (strict F1 ~50 % → ~1 %). Offsets must be verified in Unicode code points across Python and TypeScript (already a trial rule).
10. **Licences to record if adopted.** Apache-2.0: OPF, OpenMed, Fastino GLiNER2-PII, urchade, knowledgator, Presidio-MIT, Gitleaks-MIT, detect-secrets, PAPILLON-MIT, IBM PUFT. Non-standard: nvidia/gliner-PII (NVIDIA Open Model License), LFM2.5 (lfm1.0), Piiranha (CC-BY-NC-ND), TruffleHog (AGPL-3.0), Llama-based anonymisers (Llama licence), SEAL/GRASP/Need-to-Know/PRvL weights (unstated).
11. **Open owner questions.** Which packet types are in scope for cloud help first (critique only, or plans/code/schemas)? Is a consistent-pseudonym packet acceptable, given that the owner approves bytes that still contain `[PERSON_1]`-level structure and therefore facts? What latency per packet is acceptable for S4 (minutes)? Should the 27B's S4 output ever be *required* (blocking) or only advisory beside the owner's diff? Is a 40-packet synthetic derived-material corpus within the owner's ~2 h/week?
