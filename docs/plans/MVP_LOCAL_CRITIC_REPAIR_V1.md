# One local draft, one critique, one bounded repair

Status: Approved for implementation and offline/loopback verification under the
continuing owner routing goal. No real model request is authorized by this plan.
A fresh live episode requires separately frozen inputs, exact cost authority and
independent acceptance. Earlier failed assignments stay closed.

The fixed two-artifact critic signal passed independent source adjudication.
Implement a new opt-in `local_critic_repair` policy inside one accounted coding
episode. Existing policy names retain their meaning and the default stays cloud.
A checked local draft receives one tool-free critique; an acceptable verdict
retains that source, while repair-required permits one bounded local repair.
Neither a verdict nor visible checks constitute independent patch acceptance.

Use eight draft calls, at most four repair calls and one critic: twelve cumulative
local calls and thirteen model calls total. Each local phase reserves two calls
for a fresh check and explicit submission; unused draft allowance cannot enlarge
repair. Use final-only phase scheduling because existing repair-window schedules
require at least five calls. Preserve the single episode deadline, accounting and
source history. Reserve critic cost/request/time before draft work exhausts them.
There is no implicit full cloud solver, retry, second critique or second repair.
Insufficient time, unknown cost or inability to finish is recorded as failure.

Before critic dispatch, the host independently reconstructs the provisional patch
against its trusted original materialized source. Bind complete public context,
source/patch identities, original objective and visible command to the exact body.
Do not upload evaluator content, known findings or route/cost labels. Oversized,
unsupported or incomplete context stops without truncating required source.
Reuse the existing 8,192-output cloud envelope and exact configured provider
admission; Sol retains medium reasoning and explicit cache controls.

The worker dispatches the host-bound body once and settles usage before sending
a bounded visible response envelope. The host's existing strict critic parser
validates verdicts and source citations; an invalid or insufficient response stops.
Persist a typed immutable source-bound receipt and its once-only repair authority.
A repair invalidates previous check/submission authority and the critic's currency
for final source. Feed only the actual parsed guidance, labeled as advice to verify,
with the whole public task. Final export remains against the original baseline,
with fresh source/check linkage and explicit submission. Never label a repaired
patch as approved by the earlier draft critique.

Implement contracts/configuration, pure router transitions, host admission and
replay, trusted context construction and runtime orchestration together. Validate
fixed budgets, duplicate/stale/unknown/cancelled decisions, exact response charging,
source invalidation and history compatibility. Real loopback HTTP/Python/Docker
fixtures must exercise acceptable/no-repair, actual feedback/repair, invalid and
unknown critic outcomes. These fixtures use synthetic responses and prove runtime
mechanics only. Preserve original runtime and provider tests where affected.

After mechanics and independent review pass, preregister a fresh complete policy
episode and evaluator. Charge all failed work and escalation. Only a fresh quality,
cost-per-accepted-task and latency comparison can establish progress toward the
20-percent API savings / 25-percent median-latency gates with no additional
