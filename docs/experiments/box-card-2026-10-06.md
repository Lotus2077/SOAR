## Inference server

The first checklist run matched vLLM's engine-core subprocess rather than the API
server, so its flags are **unverified**: every launch flag read "no", speculative
decoding read "none" (the serving card shows it active), and `/version` was
unreachable on the default port. The API server is a `python3` wrapper listening on
all interfaces. The checklist now finds the process that answers `/v1/models` and
reports its flags; the owner should rerun it.

Environment flags on the engine process: usage statistics not disabled
(`VLLM_NO_USAGE_STATS` and `DO_NOT_TRACK` unset), Hugging Face offline mode unset.
No API key or token variables were set.

## What runs on the box

- Package repositories: Ubuntu ports, Docker, NVIDIA.

## Hardening gaps (owner actions before Tier O)

| Gap | Observed | Action |
| --- | --- | --- |
| Agent server exposed | `opencode` bound to all interfaces | Bind to loopback, or firewall it |
| Inference server exposed | API server on all interfaces, no API key, wildcard CORS | Loopback plus SSH/WireGuard tunnel; `--api-key` as defence in depth |
| SSH | Password authentication enabled; root login key-only | `PasswordAuthentication no` |
| Vendor account | `rm01` present with a password set (changed 2026-06-04) | Remove or lock it |
| Firewall | nftables input has no base chain (everything open); output accept | Default-deny input; allow SSH and the tunnel only |
| Crash and usage reporting | apport enabled, crash dumps piped to apport, autoreport timer on; vLLM usage stats not disabled | Disable apport/whoopsie; set `VLLM_NO_USAGE_STATS=1`, `HF_HUB_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1` |
| Data at rest | No encrypted block device; swap active | Disable or encrypt swap; consider LUKS for a portable box |
| Radios | Wi-Fi and Bluetooth services running | Disable if unused |

Until these are done the endpoint carries only public or synthetic data, which is
the plan's current rule anyway.

## Consequences for the plan

- 128 GB confirmed: the Qwen3.8-Flash-Next community build is a valid later speed
  lever (plan rule R2).
- Docker on the box: running SOAR's aarch64 sandbox there (always-on host) is
  feasible later, with a memory budget.
- Tier O depends on the owner's hardening list above plus a packet-capture canary,
  not on vendor cooperation.
