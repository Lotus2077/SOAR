# One local website repair with independent acceptance

Status: **Preparation approved; runtime admission remains conditional.**

## Deliverable

Use the current desktop's local-only general task to repair the preserved failed
synthetic procurement website. The task receives the original supplier data,
policy and requirements, plus an unchanged copy of the failed HTML. It must
produce one working HTML file and check its own work. No evaluator, gold,
reference implementation, numerical answers or root-authored repair is supplied.

This is a new, exposed development iteration. The old exhausted website job stays
closed. A successful repair would establish one useful website deliverable under
these conditions. It would not establish held-out reliability, cloud routing
benefit, private-data readiness, cost savings or completion of the full MVP.

complete its baseline observation of the unchanged failed file. Retain every

Use only the installed pinned offline artifact image, with no pull or install.

Launch one fresh task. An unknown operation or exhausted budget ends it; no
same-job replay, automatic replacement or deadline reset. Preserve its local
checks and terminal explanation even if it produces no usable artifact. Export
through the normal app without changing the candidate after execution.

source arithmetic independently. Require the complete interaction, money,
eligibility, invalid-input, keyboard, external-resource and responsive matrix.
