# One real consultation on the preserved website failure

Status: **Preparation approved; real runtime not admitted.** The source and
control checks below do not authorize a model request. No real consultant has
been used in this trial.

## Question and outcome

Can one cloud consultation help the local coordinator repair the previously
rejected synthetic procurement page? Use a fresh general task in the existing
desktop loop, with the exact original supplier data, policy and requirements,
plus an unchanged copy of the failed HTML. The earlier job remains closed and
its failed outcome remains recorded. This is an exposed diagnostic trial;
it cannot establish held-out quality or savings.

Ask the local coordinator to consult once on all four admitted files before
editing, then implement and verify its repair. Do not supply evaluator gold,
hidden control cases, reference code or numeric answers to either model.
Preserve the before file and export the final HTML without hand repairs.
The independent evaluator recomputes source arithmetic and exercises the
original requirements, including exact-decimal conversion, visible ineligible
totals, validation, keyboard operation and responsive views. Human visual review
and ledger/export/cleanup joins remain necessary for artifact acceptance.

## Proposed provider profile

Direct OpenAI Chat Completions at `https://api.openai.com/v1/chat/completions`,
snapshot `gpt-4.1-2025-04-14`, explicit `service_tier: default`, tool-free,
nonstreaming, maximum 2,048 output tokens and a 120-second transport timeout.
The official standard input/cached-input/output prices checked for this proposal
are USD 2/0.50/8 per million tokens. In the application's integer units these are
2,000,000 / 500,000 / 8,000,000 micro-USD per million tokens.
[Official model documentation](https://developers.openai.com/api/docs/models/gpt-4.1)
and [tier/API reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

The proposed one-consultation cap is **USD 0.10**. The exact grant must use the
smaller calculated reservation for the actual prepared packet; it cannot silently
increase the cap. The request must fit the existing text/body limits. A different
provider, model, tier, prices, account or credential requires a new explicit
profile and exact approval, never an automatic fallback. Credentials remain
session-only. No private user material is part of this diagnostic.

This choice is based on documented compatibility, not a successful API call.
Account/model access, funds, current session credential and actual HTTPS response
remain unverified. The first useful task can also supply this bounded transport
proof; there is no additional arithmetic-only paid probe in this plan. A failed
or unknown response is retained and ends the consultation without retry.

## Concrete stages

1. Verify the new default-tier helper, durable usage/fee checks and safe profile
   diagnostics. Qualify the separately versioned website evaluator against all
   thirteen retained controls and three additional selector controls. The old
   evaluator and failed results remain unchanged. Infrastructure failure must
   not count as a correct negative control.
2. Rebuild and freeze the app. Exercise four actual consultation desktop cases
   using controlled HTTP replies with the standard-tier field: approval/restart,
   decline, revocation and invalid-response no-replay. Bind the current proof
   separately from the earlier eight-case runtime.
3. Configure the explicit session profile in the same shell that will launch
   SOAR. The safe `pnpm check:general-consultant` command checks syntax without
   contacting any provider. Record a concrete real-runtime admission only after
   the profile, input/source bindings, current proof and trial limits are ready.
4. The staged `prepare` driver launches the normal app and starts one fresh
   task. **This stage uses the real local coordinator.** It stops when that model
   requests consultation, saves the exact packet/preview and closes the app
   cleanly without approving or sending to the consultant. The packet cannot be
   predicted or approved before this local action produces it.
5. Review the exact packet and maximum charge. A separate explicit decision,
   bound to the saved job/proposal/preview/checkpoint/profile and expiry, allows
   `continue` to reopen the same task and perform at most one consultation.
   Approval waiting consumes the original fifteen-minute task deadline. If it
   expires, leave the job expired; do not extend the clock or silently create a
   replacement. Arrange the trial when the owner can review promptly.
6. Preserve validated model/tier/usage, receipt and advice, local continuation,
   unchanged inputs and exact exported bytes. Independently evaluate the result
   and inspect every required view. Report success or failure and all actual
   calls/settled fees/unknown reservations without substituting manual output.

The original maximum twenty model calls, thirty tool actions, forty broker
requests and fifteen minutes remain. The consultant consumes one ordinary model
allowance. Public fetches are disabled for this synthetic task. The installed
pinned offline artifact image is reused without downloads or networked tools.
The local endpoint must pass the existing readiness/admission checks and remains
restricted to synthetic material; it has not been qualified for real private data.

Preparation evidence and the staged adapter live under the ignored trial
directory. They are not shipped credentials, model traces, gold or runtime
artifacts. The full MVP also still requires accepted research/website work,
practical input/output handling, actual private-boundary qualification and owner
acceptance; this experiment does not redefine those requirements.
